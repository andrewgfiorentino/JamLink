# Security

## Current Internet-test posture

JamLink's two-peer test transport encrypts and authenticates every UDP datagram with AES-256-GCM through Windows CNG. The room key is 256 random bits generated by the operating system and carried in the private `JL1` invite. Packet headers are authenticated, sequence replay is rejected, and a connected peer endpoint is pinned.

The invite is a bearer credential. Anyone who receives it can try to join while the host is running. Do not post it publicly. JamLink does not persist or intentionally log the invite, and leaving the room destroys the in-memory transport.

## Trust boundaries

- Qt/QML owns presentation only and never receives raw cryptographic state other than the user-visible invite.
- the network worker owns sockets, DNS/STUN, UPnP, packet parsing, and cryptography;
- audio callbacks exchange samples only through bounded SPSC queues;
- Cloudflare STUN is used only for public-address discovery and sees a source IP/port, not audio or the secret;
- UPnP can request a router mapping and removes the mapping during orderly shutdown.

## Not yet provided

- no independent security audit or parser fuzz campaign;
- no forward secrecy, identity/account verification, key rotation, or relay authentication;
- no protection if the invite is copied, intercepted at the messaging layer, or reused while the host stays active;
- no protection from traffic analysis, denial of service, compromised endpoints, or malicious local audio devices;
- no relay for networks that cannot accept direct UDP.

This build is appropriate only for a limited, mutually trusted two-person test. Report security issues privately to the repository owner rather than including a live invite or personal IP address in a public issue.
